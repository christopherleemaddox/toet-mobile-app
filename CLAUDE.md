# TOET Mobile App — daily encouragement cards

## What it is
A Bible-based affirmation/encouragement card app: 7 categories, 92 topics, **1,841 cards** (corrected 2026-08-07 — verified by parsing `window.CARDS`; an older "461" figure was stale documentation, not a real count). Each card gives a "truth" (a personalized affirmation grounded in a verse), the verse/reference, and a related prayer. **No free/premium split** — every user gets full access to everything. There was an earlier premium-tier direction (see "Decided" below); Christopher deliberately abandoned it to keep the app simple.

Fixed both ends: full OG/Twitter/description/canonical tags went in the **outer** static shell (what crawlers see), and a matching `<title>` went into the **inner** template's head too (what the real browser tab shows after the swap) — confirmed via `document.title` in the browser before/after. og:image points at `icon-512.png` (square, not an ideal 1200×630 social-card shape, but functional) — a proper social-card image would be a nice-to-have later, not a blocker.

## Reading Live Build or App Blueprint's real source
Both are exported from an AI app-builder as a "DC-runtime" bundled HTML file — the actual content is compressed/encoded, not plain text, so grepping for copy or component names comes back empty even though it's there. Use the **`read-dc-bundle`** skill (`.claude/skills/read-dc-bundle/`) instead of re-deriving this from scratch — it took a full investigation to figure out the file format the first time (2026-08-06); it should be a two-minute lookup every time after.

It was leftover UI from the abandoned premium direction: a "Create an account · See plans →" entry point in Settings, and a 5-step flow (pitch → plans/pricing → sign-up form → fake payment → welcome) explicitly labeled "PREVIEW · NOT YET LIVE." It was honest about being non-functional (no payment processor existed — zero `fetch`/network calls anywhere in the app), but completing it wrote a persistent, real-looking `{name, email, plan, since}` object to `localStorage['toet.account']`, which then made Settings display an actual "Yearly plan · since Aug 2026 · Manage plan" state with nothing behind it — a real risk of a curious user believing they'd signed up for something. Removed via direct source edit (see below), not just a UI hide, so there's nothing dormant left to accidentally re-expose.
  - **How it was done, for future reference:** `Live Build/index.html` is a DC-runtime bundle (see "Reading Live Build" below) — there's no visual editor, so the fix was a scripted edit: decode the `__bundler/template` JSON string with Python, remove the exact HTML/JS spans for the Settings entry point, the 5-step modal, the constructor's account-related state fields, and the `renderVals()` IIFE that computed all the account bindings — verified each removal matched exactly once before applying — then re-encode with `json.dumps()` and **re-escape every literal `</` back to `</`** (the original encoder does this so a literal `</script>` inside the JSON string can't prematurely close the outer `<script>` tag in the browser's HTML parser; `json.dumps()` alone doesn't do this and produces a file that fails to load — hit this exact bug once, fixed by replicating the escaping). Tested in the browser (fresh tab, checked console for errors) before replacing the real file. The same process was applied to `App Blueprint/TOET-Blueprint.html` to remove the now-nonexistent Account screen (A1–A6) and its Settings entry (S2), keeping the mandatory Blueprint-sync rule. A backup of both pre-edit files exists in this session's scratchpad if anything needs to be diffed later, but git history is the durable record.
